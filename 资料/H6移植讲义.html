H5 → H6 霍尔芯片移植讲义

工程
EM_HapticMouse，LPC11U35，板型 GT_LINA_T1A_H5_PWM
目标
霍尔驱动从 H5（GTRY154）改为 H6（GTRY164）
前提
手上只有 H6 的板子，没有 H5 的板子
代码未经验证。讲义里的代码是对照芯片手册和 XENO 工程写的，没有编译过，也没有上板验证过。每个数值后面都标了来源，遇到和实测不符的地方，以实测和手册为准。

怎么用这份讲义

  1. 一次只改一件事，改完就验证。时序错、校验位错、寄存器值错，现象都是“读出来不对”。一口气全改完再烧录，你将无法分辨是哪一个错。
  2. 上一步没通过，不做下一步。每一步末尾都有通过标准，是具体的数值，不是“看起来正常”。
  3. 每通过一步，提交一次，并填记录表。出问题时能退回到上一个确定正常的状态。

没有 H5 板子带来两个后果，讲义已经按此调整：

  • 你没有“已知正常”的硬件可以回退。所以第 1 步用“编译结果逐字节相同”来证明重构没改坏，而不是上板测试。
  • 你没有 H5 的原始值作为手感基准。准备工作里列了替代办法。

页面上的勾选和记录表内容保存在这台电脑的浏览器里，换电脑或清除浏览器数据后不会保留。重要的实测值请同时记到别处。

背景知识

这颗芯片是什么

  • H5 = GTRY154，H6 = GTRY164，都是 G.TECH 的霍尔传感器，封装和引脚相同。
  • 它检测按键下方磁铁的远近，输出一个 14 位数值（0–16383）。没有磁场时约为 8192，磁铁靠近时数值向一边偏。
  • 手册（datasheet）在 资料/ 目录，文件名以 GTRY164（H6）和 GTRY154（H5）开头。

这块板子怎么接的

两颗芯片串成一条链（菊花链），共用三根线接到 MCU 的 SSP1，没有片选线。下表已对照原理图 GT_Lina T1A Hall Haptic POC_SCH_V0.1.pdf 核对，与代码一致。

信号MCU 引脚出处
SCKPIO1_15src/SPI.c:227
MOSI（芯片的 SDI）PIO0_21src/SPI.c:216
MISO（芯片的 SDO）PIO0_22src/SPI.c:221
Hall_PWR_EN（霍尔电源开关，高电平上电）PIO0_16inc/my_board.h:363、src/GPIO.c:577-584
  • SPI 配置是 CPOL=0、CPHA=1、8 位，时钟 48MHz ÷ (8 × 3) = 2MHz（src/SPI.c:238-239，旁边注释写的 8MHz 是错的）。手册要求高于 1MHz，满足。
  • 链的顺序是 MOSI → H1（左键）→ H2（右键）→ MISO。离 MISO 最近的 H2 先被读出，所以一次传输的 4 个字节里，hall_spi_rx[0..1] 是右键，hall_spi_rx[2..3] 是左键。
  • 霍尔芯片由 VCC3.3V 经 PMOS（MOS1）开关供电，和 MCU 是同一路 3.3V。固件上电时先把 Hall_PWR_EN 拉低 50ms 再拉高，调试中芯片状态乱了可以用这个脚断电重来。
  • 两颗芯片的 PWM1–PWM4 全部悬空，板上没有接 LED，LED 相关寄存器不用配。
  • 电磁线圈（7V 驱动）按设计就布置在霍尔芯片旁边，通电时的磁场会影响霍尔读数。代码里“振动期间不采用霍尔值”的逻辑（USE_HALL_VALUE_DURING_VIBRATION）就是为此而设。

“TD 时间”是什么

因为没有片选，MCU 通过把 SCK 拉高一段特定时长来告诉芯片要做什么。时长不同，命令不同。这个时长就是手册 7.8 节的 td。

命令SCK 拉高时长之后的等待作用
HAL_CONVERTtd1 = 5us ±5%td2：连续模式 >4us，单次模式 >24us读采样
Interrupt_Mode_ENtd3 = 12us ±5%—进中断模式（不用）
W_PWM_REGtd4 = 18us ±5%td5 >3us写 LED 的 PWM
WR_REGtd6 = 39us ±5%td5 >3us结束一次读/写寄存器
SLEEPtd7 = 28us ±5%—休眠（不用）
FREQ_Calibratetd10 = 128us ±5%td12 >50us频率校准
Soft_RSTtd11 >1280ustd9 >50us软复位

±5% 的意思是：39us 的命令，实际脉宽必须落在 37.05–40.95us。所以同事说“TD 时间要自己量”。

四种帧格式

对应手册 7.2–7.6 节的时序图。

读采样

先发 5us 脉冲，等 td2，再打 16 个时钟，每颗芯片吐出 16 位。

bit15  bit14  bit13 ............ bit0
CRC1   CRC0   D13 ............... D0
CRC0 = D0^D2^D4^D6^D8^D10^D12
CRC1 = D1^D3^D5^D7^D9^D11^D13

读到 0xC000 或 0x3FFF 表示芯片状态异常，需要复位。

写寄存器

先移入 16 位，再发 39us 脉冲。

bit15  bit14   bit13..bit8   bit7..bit0
1      CRCWR   地址 A5..A0   数据 D7..D0
CRCWR = A5^A4^A3^A2^A1^A0 ^ D7^D6^D5^D4^D3^D2^D1^D0

CRCWR 算错，芯片直接丢弃这次写入，不报错。

读寄存器

先移入 16 位（bit15 = 0，地址同上，数据任意），发 39us 脉冲，再打 16 个时钟，读回 16 位，低 8 位有效。

频率校准

发 128us 脉冲，等 td12，再打 16 个时钟（SDI 保持 0），读回 16 位，低 8 位有效，合格范围 0x7C–0x84。

最大的坑。现有代码按编号使用宏：写寄存器用 TD4_DELAY_US，频率校准用 TD7_DELAY_US。而 H6 那组宏里 TD4 = 18us（写 PWM）、TD7 = 28us（SLEEP）。只把 USE_HALL_SENSOR 改成 6，结果是写寄存器变成写 PWM、上电校准变成让芯片休眠，而且编译不报任何错。第 1 步专门解决这个问题。

第 3 步频率校准，证明芯片在回应

目标：第一次确认“MCU 发的命令芯片听懂了，芯片回的数据 MCU 读对了”。

typedef struct

uint8_t Hall_osc_calibrate(void)
{

	g_hall_dbg.freq_ok = 0;

	for(times = 0; times < 128; times++)
	{
		/* H6 手册图 9：校准读回期间 SDI 必须为 0 */
		hall_spi_tx[0] = 0;

第 4 步改校验位，写一个寄存器再读回

目标：证明写寄存器的帧格式和校验位是对的。

改动

先修一个现有的笔误。app/button.c:921 和 :923 把 rx 改成 tx：

	hall_spi_tx[1] = 0x55;//any value
	hall_spi_tx[3] = 0x55;//any value

在 Hall_write_register 后面加一个写单个寄存器的函数，并在 inc/button.h 加声明：

void Hall_WriteReg(uint8_t reg, uint8_t data)
{
	uint8_t j;
	uint8_t head;

#if (6 == USE_HALL_SENSOR)
	/* H6：校验位 = 6 位地址和 8 位数据一起求奇偶 */
	head = reg | 0x80 | (bit_crc_write_reg[data] ^ bit_crc_write_reg[reg & 0x3F]);
#else
	/* H5：校验位只算 8 位数据 */
	head = reg | 0x80 | bit_crc_write_reg[data];
#endif

	for(j = 0; j < 2; j++)
	{
		hall_spi_tx[j * 2 + 0] = head;
		hall_spi_tx[j * 2 + 1] = data;
	}

	Hall_write_register();
}

为什么异或一次就行：bit_crc_write_reg[x] 返回的是“x 的奇偶，放在 bit6”。两个奇偶值异或，就是把两段合起来算的奇偶，位置仍在 bit6，正好是帧里 CRCWR 的位置。

把 ana_hall2_phy_set_mode（app/button.c:938）改成调用它，这样校验逻辑只有一处：

void ana_hall2_phy_set_mode(unsigned char length)
{
	unsigned char i;

	(void)length;
	for(i = 0; i < REG_CNT; i++)
	{
		Hall_WriteReg(sensor_reg_init_array[i][0], sensor_reg_init_array[i][1]);
	}
}

把第 2 步临时加的那行读寄存器换成一段写读测试：

	Hall_WriteReg(0x30, 0x21);                              /* 0x30 默认值是 0x20 */
	Hall_ReadReg(0x30, (uint8_t *)&g_hall_dbg.reg_rd[1],    /* 左键 */
	                   (uint8_t *)&g_hall_dbg.reg_rd[0]);   /* 右键 */

选 0x30 的原因：它是“基线正偏差”，只有打开芯片内基线功能才起作用，本项目不开，改它没有副作用。

不通过怎么查

读回值含义
0x20读是通的，写没生效。校验位算错，或 39us 脉宽不对
0x00 / 0xFF读本身不通。回第 2 步量 39us
一个 0x21 一个 0x20两颗芯片收到的帧不一样，检查 tx[0..1] 和 tx[2..3] 是否都填了

反向实验

为了确认校验位确实在起作用，故意把 ^ bit_crc_write_reg[reg & 0x3F] 去掉，再写一个地址奇偶为 1 的寄存器，写入应当失效。0x30 的二进制是 110000，奇偶为 0，测不出来；换 0x31（110001，奇偶为 1）来做。做完改回来。

通过标准

g_hall_dbg.reg_rd[0] 和 reg_rd[1] 都是 0x21；反向实验中写入失效。

提交信息：H6：写寄存器校验位包含地址，并验证读写

关于这张表的三个决定：

  • 0x33 只开连续转换（0x80）。XENO 工程用 0x84，多开了芯片内部的基线跟踪。但本工程的基线是 MCU 在 src/my_misc.c:135-290 自己算的，两套同时开会互相干扰，所以不开。
  • 只写手册里有的寄存器。XENO 还写了 0x13、0x15、0x16、0x18、0x1C、0x1E、0x20、0x25 这 8 个手册里查不到的地址，这里没有放。见要问同事的问题。
  • LED 关着。原 H5 配置里灯是开的，但原理图显示两颗芯片的 PWM 脚都悬空，板上没有灯，所以 0x05–0x08 和 PWM 都不用配。

HallSensor_INIT 恢复并加上读回校验：

void HallSensor_INIT(void)
{
	uint8_t i, l, r;

	Hall_osc_calibrate();

	ana_hall2_phy_set_mode(2);

	for(i = 0; i < REG_CNT; i++)
	{
		Hall_ReadReg(sensor_reg_init_array[i][0], &l, &r);
		if((l != sensor_reg_init_array[i][1]) || (r != sensor_reg_init_array[i][1]))
		{
			g_hall_dbg.reg_rd[0] = sensor_reg_init_array[i][0];   /* 记下第一个出错的地址 */
			g_hall_dbg.reg_rd[1] = l;
			break;
		}
	}
	if(i == REG_CNT)
	{
		g_hall_dbg.reg_rd[0] = 0xAA;                              /* 0xAA = 全部一致 */
	}

	CT16B1_DelayUs(100);   /* 手册 0x33 说明：切换转换模式后至少等 50us */
}

通过标准

g_hall_dbg.reg_rd[0] == 0xAA。否则它是第一个读回不一致的寄存器地址。个别寄存器可能读回值带保留位，把地址和读回值记下来，对照手册该寄存器的说明判断。

第 7 步按键与增益

目标：按键全行程对应的数值变化量足够大，且不饱和。

装好按键，分别记录左右键“松开”和“按到底”的 raw，算出差值。

怎么判断增益是否合适

没有 H5 实测基准，下面前两条是经验判据，不是手册要求。拿到同事的参考值后以参考值为准。

  • 松开和按到底的数值都离 0 和 16383 留出一千左右的余量，否则有饱和风险。
  • 差值应远大于第 6 步记录的静止抖动。代码把全行程分成 100 段（MAX_SEGMENT），差值如果不到抖动的 100 倍，分段值会跳动。
  • 代码要求差值不小于 100（src/my_misc.c:301），这是硬下限。

调增益

改 0x0B 时必须同时改 0x09、0x29、0x2A，四个是联动的。

LNA 增益0x090x0B0x290x2A
16x0x000x850x500x20
24x（当前）0x200x850x600x28
48x0x200x950xA00x40
96x0x200xA50xF00x60

0x0B 的低 4 位是 PGA，0x5 = 19.2x，范围 0x0–0x9，可做细调。0x09 的低 4 位是 LED 最大电流，表里按关灯写的。

按键方向

现在 inc/my_misc.h:40-41 定义 PRESS_KEY_AND_VALUE_INCREASE 为 0，即“按下时原始值减小”。如果实测按下时数值变大，把它改成 1。
