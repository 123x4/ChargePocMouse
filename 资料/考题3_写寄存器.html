考题三：写寄存器 0x30 再读回

只考一件事：H6 的写校验位 CRCWR 算对没有。算错了芯片会直接丢掉这次写入，读回来还是旧值。

记住三件事

1 C AAAAAA

写帧第一个字节：最高位 1 表示写，第二位是 CRCWR，后 6 位是地址。第二个字节是数据。

B0 21

写 0x30 = 0x21：地址 110000 有 2 个 1，数据 00100001 有 2 个 1，一共偶数个，CRCWR = 0，首字节 = 0xB0。

写完读回

写操作芯片不回话，只能用考题二的方法读回来看。最后再写回默认值 0x20，芯片恢复原状。

怎么跑这一关

  1. 本地先把考题二的 HALL_EXAM2_PULSE_US 改回 39，再 git pull。代码里 HALL_EXAM 已经是 3。
  2. Keil Rebuild，0 Error 后烧录。先开 python tools/hid_log.py，再插 USB。
  3. 每组三行，看最后一行： 
    EXAM1 CAL ok=1 ...
EXAM2 RD 0x0C rx=00 AA 00 AA ...
EXAM3 WR 0x30=21 -> R=21 L=21 | =20 -> R=20 L=20 crc=ok (expect 21 21 | 20 20)
  4. 对照实验：把 HALL_EXAM3_BAD_CRC 改成 1，重新烧录。预测：R=20 L=20 | R=20 L=20 crc=bad，两次写都被拒，读回的都是默认值。看完改回 0。
实测结果：本关通过。

CRC 正确：21 21 | 20 20；CRC 取反：20 20 | 20 20，和预测一致。芯片确实检查 CRCWR，算错就丢掉这次写入。

这一关验证不了的东西

CRCWR 要把地址和数据一起算（手册公式），而原来 H5 的表只算数据。0x30 = 110000 的 1 是偶数个，两种算法在这里结果一样。所以这一关只能证明“芯片会检查校验位、我们算的对”，证明不了“地址那一项算没算进去”。 这要留给考题四：例如写 0x2F = 0x14，新算法得到首字节 0xEF，H5 的算法会得到 0xAF，按手册芯片应该只接受前者。

手册：H6 §7.4 图 6（PDF 第 9～10 页）写帧格式和 CRCWR 公式；§7.8（第 12 页）td6 = 39 µs、td5 > 3 µs；寄存器表（第 16 页）0x30 默认 0x20。
