考题四：CRCWR 里的“地址那一项”

只考一件事：H6 的校验位必须把地址也算进去。照搬 H5 的老算法（只算数据），换一个地址就会被芯片拒收，而且不报任何错。

记住三件事

0x31 = 110001

地址里有 3 个 1，是奇数。考题三的 0x30 是偶数个，两种算法碰巧一样，所以这一关换了地址。

F1 vs B1

写 0x31 = 0x21：H6 算法首字节 F1，H5 算法 B1。只差 bit6 这一位。

不报错

算错的写入芯片直接丢掉，MCU 什么都不知道。只有读回来比对才能发现。

怎么跑这一关

  1. 本地先把 HALL_EXAM3_BAD_CRC 改回 0，再 git pull。代码里 HALL_EXAM 已经是 4。
  2. Keil Rebuild，烧录。先开 python tools/hid_log.py，再插 USB。
  3. 看第四行： 
    EXAM4 WR 0x31=21 head=F1 -> R=21 L=21 | =20 head=B1 -> R=20 L=20 crc=h6 (expect 21 21 | 20 20)
  4. 对照实验：把 HALL_EXAM4_H5_CRC 改成 1，重新烧录。预测：head=B1 -> R=20 L=20 | head=F1 -> R=20 L=20 crc=h5，两次都被拒。看完改回 0。
实测结果：本关通过。

H6 算法：head=F1 → 21 21 | head=B1 → 20 20；H5 算法：head=B1 → 20 20 | head=F1 → 20 20，和预测一致。

两步都符合预测，就证明了：H6 的写入必须用新公式，H5 的那张 bit_crc_write_reg 表不能直接拿来用。

手册：H6 §7.4 图 6（PDF 第 9～10 页）CRCWR = A5^…^A0^D7^…^D0；H5 §7.4（GTRY154 手册第 8 页）CRCWR = D7^…^D0；寄存器表（H6 第 16 页）0x31 默认 0x20。
