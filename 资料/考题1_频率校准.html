考题一：频率校准

只考一件事：MCU 在 SCK 上做出的 128 µs 高电平，H6 芯片认不认。

记住三件事

128 µs

芯片用这个脉冲当“标准尺”，把自己的时钟调到和 MCU 一致。之后 39 µs、5 µs 的命令都按这把尺量。

7C～84

回值是芯片量到的脉宽（0x80 = 正好）。每发一次芯片调一点，进入这个范围就算过。

20 ms

成功后照手册等 20 ms 再往下走。只在开机跑一次。

怎么跑这一关

  1. git pull，Keil Rebuild，0 Error 后烧录。
  2. 先运行 python tools/hid_log.py，看到 waiting 后再插 USB。开机约 2、4、6 秒各打印一次 EXAM1，之后就安静了（其他日志都已关掉）。
  3. 正式考，应该看到： 
    EXAM1 CAL ok=1 n=.. R=00:7C~84 L=00:7C~84 width=128
  4. 对照实验（已做）：把 HALL_EXAM1_PULSE_US 改成 145，结果是： 
    EXAM1 CAL ok=1 n=17 R=00:83 L=00:84 width=145
EXAM1 seq  R=96 94 92 91 8F 8D 8B 8A ...
    做完记得改回 128。
  5. 可选的预测实验：改成 124。按上面的理解，第一次读数就该在 0x80 附近，n=1。说中了，说明这套理解是对的。
对照实验推翻了原来的假设。

原来以为芯片会拒绝 ±5% 以外的脉宽，所以预测 145 µs 会得到 ok=0。实测芯片照收不误：先量出 150，再每次把自己的时钟调慢一点，第 17 次进了范围。 所以这一关能证明的是：两颗芯片都收到校准命令，并能把时钟收敛到范围内。它判不出 MCU 的脉宽准不准，这要交给考题二：如果校准用的脉冲偏了，芯片的尺子跟着偏，39 µs 的读寄存器命令就会对不上。

这也解释了“为什么总是 0x84”：128 µs 第一次量出来是 84～86，芯片从上往下调，一进范围就停，所以总停在上沿。

采样值乱跳、右键乱触发是后面几关的事，现在不用管。
