考题一：频率校准

这一题考 MCU 能不能在 SCK 上做出一个 128 µs 宽的高电平，再老老实实等够 50 µs。做对了，两颗 H6 会各自回一个 0x7C～0x84 之间的数；做错了，它们什么都不回。你的新板已经答对了，这份讲义带你看清它是怎么答对的。

先记住一句话H6 只有一根 SCK 线听命令。它不看数据，只看 SCK 保持高电平多久：高 5 µs 是“采样”，高 39 µs 是“读写寄存器”，高 128 µs 就是“频率校准”。所以 MCU 要临时把 SCK 从 SPI 手里借过来，当普通 GPIO 自己拉高、计时、拉低。

0怎么跑这一关

代码已经调成“只做考题一”：HALL_EN 给芯片上电以后，第一件事就是频率校准，前面不发软复位（手册 §9.1 图 11，PDF 第 19 页）。这样这一关只考 128 µs 这一条命令。开关在 app/button.c 里 g_hall_chk 定义的下面：

#define HALL_EXAM             1   /* 1 = 只做频率校准 */
#define HALL_EXAM1_BAD_WIDTH  0   /* 1 = 故意发 145 us（对照实验） */
#define HALL_DIAG_PINS        0   /* 1 = 再跑一遍以前的引脚 / 回环检查 */

为什么还要做第 6 步一个检验只会说“通过”是不够的，还要证明它在该失败的时候真的会失败。145 µs 落在 121.6～134.4 的窗口外面，芯片应该不认这条命令。如果这时还显示 ok=1，说明这道题根本判不出对错，第 5 步的“通过”也就不可信。两步结果都对，这一关才算过。
这时候不用管的东西日志里的 ProcessRecvSampleRawData 数值乱跳、右键反复触发，是因为 H6 寄存器还没初始化、采样还没移植（考题四、五）。这一关只看 EXAM1 那一行。

2芯片的秒表：高电平宽度决定命令

拖动滑块，改变 SCK 高电平的宽度，看芯片会把它当成哪条命令。每条命令只允许 ±5% 的误差，128 µs 的合格窗口是 121.6～134.4 µs。

为什么普通的 SPI 时钟不会被误认成命令SSP1 跑 2 MHz，每个时钟的高电平只有 0.25 µs，远小于最短的命令（2 µs 唤醒）。手册第 7 章开头就要求：当时钟用的时候 SCK 频率必须高于 1 MHz，正是为了让“数据时钟”和“命令脉冲”分得开。

3代码里的 128 µs 是怎么凑出来的

代码写的不是 128，而是 DELAY_OUT(128)，最后真正的高电平宽度由三部分加起来。

#define DELAY_OUT(x)     (x - 1)
#define TD10_DELAY_US    (DELAY_OUT(128))   /* = 127 */
#define HALL_TD_FREQ_CAL TD10_DELAY_US

CT16B1_DelayUs(127);   /* 定时器 1 MHz（PR = 47，48 MHz / 48），数到约 125 */
                       /* 加上切 IOCON、写 GPIO、函数调用约 3 µs */

结果约 128 µs，落在 121.6～134.4 的窗口正中间附近。这 3 µs 的“代码开销”是估计值，不能用尺子量出来，所以要让芯片来判：它回了 0x84，就说明它认出了这条命令，宽度一定在窗口里。

原因128 µs 脉冲被认出，两颗芯片都回了 0x84SCK 被拉在低电平，芯片根本没看到脉冲，也没有时钟把数据移出来
新板为什么是“第 2 次才过”手册图 11 的流程本来就是“发一次、检查、不合格就再发”，最多 128 次。第一次不合格，可能是芯片刚启动，振荡器还没校到范围内，也可能读回的是移位寄存器里的旧内容；手册没细说原因，但明确允许重试，所以 n=2 属于正常范围。如果以后 n 经常是几十次，才需要追查。
值得留意的一点0x84 正好是合格范围的上限（0x7C～0x84）。这次合格没问题，但它说明这颗芯片的振荡器偏在一边。以后换板子如果出现 0x85、0x86，代码会一直重试到 128 次然后失败，到时先想到这里。
这次排查里值得记住的做法旧板全是 0 的时候，我们先猜了时序、猜了芯片，真正一锤定音的是换一块新板对比。同一份代码，在两块板上结果不同，问题就在板子上。以后遇到“怎么都不对”的情况，先找一个确定是好的东西来对比。

5翻开手册对照

H6 手册 §7 开头，PDF 第 8 页芯片只靠 SCK 的高电平时间识别命令；当时钟用时频率必须高于 1 MHz；只支持上升沿输出、下降沿采样。
H6 手册 §7.6 图 9，PDF 第 10～11 页FREQ_Calibrate：拉高 td10，等 td12，再用 SPI 时序读回 16 位，低 8 位有效。所以代码只看 rx[1] 和 rx[3]。
H6 手册 §7.8 时序表，PDF 第 12 页td10 = 128 ± 5% µs，td12 > 50 µs。代码里 td12 用的是 55 µs，留了余量。
H6 手册 §9.1 图 11，PDF 第 19 页上电第一步就是频率校准；每次都要检查所有芯片的返回值满足 0x7C ≤ Data ≤ 0x84；最多 128 次；成功后延时 20 ms。
LPC11U 手册 7.4.1.40 表 115，PDF 第 116 页PIO1_15 的 IOCON：FUNC = 0 是普通 GPIO（用来发命令），FUNC = 3 是 SSP1 的 SCK（用来移数据）。
LPC11U 手册 表 301，PDF 第 338 页CT16B1 预分频 PR。代码写 PR = 47，48 MHz ÷ 48 = 1 MHz，定时器每 1 µs 加 1。
