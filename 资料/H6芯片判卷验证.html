让 H6 芯片当裁判：不焊线验证时序

杰哥说时间应该是准的。这份讲义把"准"变成 5 道考题，交给 H6 芯片自己判卷：芯片答对了，就证明对应的那条命令时长它认得。结果通过 USB 打印到电脑上，不用焊线，也不用接调试器。

一句话原理（H6 手册 §7，PDF 第 8 页）手册原文："recognizes the instruction by calculating the high-level time of SCK and performs the corresponding action"，意思是芯片靠计算 SCK 高电平持续了多久来识别命令，再执行对应的动作。所以反过来说：只要芯片做出了正确的动作，就说明它量到的时长落在了正确的档位里。我们不用自己去量时间，看芯片的反应就行。

0芯片怎么"判卷"

先用一个小实验建立直觉：点下面的按钮，选一个 SCK 高电平时长，看芯片会不会执行命令。芯片判断的依据，就是手册第 12 页那张时序表。

芯片判卷能证明什么，不能证明什么
  • 能证明：脉冲时长落在芯片"认得"的范围里，现在这套代码在这块板子上能工作。
  • 不能证明：离手册规定的 ±5% 边界还有多少余量。芯片实际容忍的范围可能比 ±5% 宽，手册没写。换一批芯片、温度变化之后还准不准，只有逻辑分析仪实测才能回答。
所以这套验证的定位是：先确认"能用"，有条件的时候再用仪器确认"余量够"。
📖 翻开手册对照
H6 手册 GTRY164 V1.9§7 开头，PDF 第 8 页：靠 SCK 高电平时长识别命令，SCK 当时钟用时频率必须高于 1MHz。§7.8 时序表，PDF 第 12 页：td1 = 5us、td6 = 39us、td10 = 128us，都是 ±5%；等待时间 td2 > 4us、td5 > 3us、td12 > 50us。
MCU 手册 UM10462表 115 PIO1_15（PDF 第 116 页）：代码把 SCK 脚的 FUNC 改成 0，变成普通 GPIO 来"按住"，改成 3 还给 SSP1 打快拍子。动画讲解网页第 5 关演示过这个过程。

1考题一：频率校准，考 128us 和"等 50us"

上电后的第一条命令。MCU 发 128us 脉冲，等待超过 50us，然后打 32 拍把结果读回来。两颗芯片的读回值都在 0x7C–0x84 之间，才算答对。

左键芯片 H1 的数据右键芯片 H2 的数据MCU 送进去的数据
📖 翻开手册对照
H6 手册§7.6 图 9，PDF 第 10–11 页：td10（128us）→ 等 td12（>50us）→ 读 16 位，低 8 位有效。图中 SDI 全是 0（V1.7 改版专门改的），所以读回时 MCU 必须发全 0。§9.1 图 11，PDF 第 19 页：读回值 0x7C ≤ Data0 ≤ 0x84 算通过，最多试 128 次，通过后延时 20ms。
为什么答对能证明时间准手册说这条命令用来"校准芯片内部振荡器"（PDF 第 11 页）。芯片要先认出这是 128us 档，才会执行校准、才会把结果放进格子。读回值不在范围内或者全是 0x00 / 0xFF，就说明芯片没认出来。
读回值为什么正好在 0x80（=128）附近，手册没有解释。我推测是芯片用自己的时钟数出了这段脉冲的长度，但这只是推测。

2考题二：读一个寄存器，考 39us

只读、不写，最安全。读寄存器 0x0C：H6 刚上电时它的值是 0xAA（二进制 10101010，很有辨识度，不容易碰巧读对）。两颗芯片都读回 0xAA，就答对了。

📖 翻开手册对照
H6 手册§7.4 图 7，PDF 第 10 页：先送 16 位（最高位 0 表示读，接着是地址，数据位随便填），再发 WR_REG 命令（td6 = 39us），然后读回 16 位，低 8 位就是寄存器的值。§8 寄存器表（PDF 第 13–17 页）：0x0C Test_Reg0 默认值 0xAA。
代码里要顺手修的Hall_ReadReg() 原来把"随便填的 0x55"写进了 hall_spi_rx，应该写进 hall_spi_tx。数据位本来就是随便填，所以这个错不影响结果，但要改正。

3考题三：写一个寄存器再读回来，考 39us 和校验位

把寄存器 0x30（默认值 0x20）写成 0x21，再读回来。读回 0x21 说明写入被芯片接受了。H6 写寄存器时校验位要把地址也算进去，这是和 H5 不一样的地方，算错了芯片会直接丢弃这次写入，而且不报错。

📖 翻开手册对照
H6 手册§7.4 图 6，PDF 第 9–10 页：bit15 = 1（写），bit14 = CRCWR，bit13–8 = 地址，bit7–0 = 数据。公式 CRCWR = A5^…^A0^D7^…^D0；"if the value of CRCWR is incorrect, the instruction is invalid"，也就是校验位错了，这条命令无效。
为什么选 0x30它是"芯片内基线"的参数，我们不打开这个功能，改了没有副作用，测完再写回 0x20。注意：0x30 的地址位里 1 的个数是偶数，地址的奇偶为 0，所以就算漏算了地址也碰巧能写成功。想真正证明地址算进去了，要换 0x31 再测一次（上面的切换按钮演示了这种情况）。

4考题四：写整张初始化表，逐个读回核对

考题三只证明了一个寄存器能写进去。这一题把 H6 的 15 项初始化表全部写进去，再一项一项读回来对比。最后一项把 0x33 写成 0x80，让芯片进入连续采样模式，为考题五做准备。

📖 翻开手册对照
H6 手册 §8 寄存器表，PDF 第 13–17 页标着 "write fix value" 的必须写固定值：0x0C=0x83、0x26=0x0A、0x27=0x05、0x28=0x04、0x2F=0x14、0x34=0x03。增益要四个寄存器一起改：0x09 的 bit5、0x0B、0x29、0x2A。0x33 默认是单次采样，bit7 写 1 才是连续采样，切换后要等 50us。
为什么 H5 的表不能用H5 表里的地址在 H6 上全部撞车：0x0B 在 H5 是采样间隔，在 H6 是增益；0x10 在 H5 是省电阈值，在 H6 是采样间隔的高位……所以切到 H6 后，H5 的那张表一项都不能写。

5考题五：读采样，考 5us 和"等 4us"

这道题每 1ms 考一次，一直考下去。每次读回的 16 位里，最高 2 位是芯片按数据算出来的校验位。校验一直通过，而且数值不是全 0 或全 1，就说明芯片每次都认出了 5us 命令。

一个容易漏掉的坑：全 0 和全 1 也能"通过"校验如果芯片根本没回应，MISO 线一直是低电平或高电平，读回来就是 0x0000 或 0xFFFF。按手册的公式算一下：0x0000 的校验位是 00，0xFFFF 的数据是 0x3FFF、校验位是 11，两个都能通过校验。所以代码里要把原始值等于 0 或 0x3FFF 的情况单独算作错误，否则会把"芯片没回应"误判成"一切正常"。
📖 翻开手册对照
H6 手册§7.2 图 4，PDF 第 8–9 页：td1（5us）→ 等 td2（连续模式 >4us）→ 读 16 位。CRC0 = D0^D2^…^D12，CRC1 = D1^D3^…^D13。第 9 页：读到 0xC000 或 0x3FFF 表示芯片状态异常。
代码里已有的校验button.c 里的 bit_error[] 表，加上 my_misc.c 里的 ana_phy_bit_error_checker2()，实现的就是这两个公式，H5 和 H6 完全一样，不用改。

考题正确答案答对证明答错时先查

7怎么做

第一步：结果怎么从芯片传到你的电脑上

MCU 把每道题的结果存进全局变量 g_hall_chk，每隔 2 秒用 InfoLog() 打印一遍。InfoLog 的输出走 USB（inc/my_debug.h，MYDEBUG_ENABLE = 1），电脑上用 main 分支里现成的 tools/hid_log.py 读出来。全程只用一根 USB 线，不用焊线，不用调试器。

第二步：操作顺序

  1. 烧 bootloader：插 USB 弹出 U 盘 → 删掉 firmware.bin → 拷入 BootLoader_2019.2.22.bin → 拔插 USB。（之前核对过：这个版本检查标志的地址是 0x3F00，和我们的程序一致）
  2. 让 Codex 改代码：把下面"给 Codex 的指令"整段复制给它。
  3. 烧应用程序：用同事给的升级工具，烧 Codex 编译出来的 Sample.hex。
  4. 看结果：电脑上安装一次 pip install hidapi，然后运行 python tools/hid_log.py。要先关掉 MouseTest.exe，它会占用同一个 USB 接口。
  5. 把打印出来的 5 行发给我，我们一起对照上面的判卷表看。

正常情况下大概会看到这样的输出（下面是示例，不是实测数据，SMP 的数值每块板子都不一样）：

8) 整个替换 Hall_osc_calibrate()：
uint8_t Hall_osc_calibrate(void)
{
  uint8_t times;

  g_hall_chk.cal_ok = 0;
  for(times = 0; times < 128; times++)          /* datasheet Fig 11: up to 128 tries */
  {
    hall_spi_tx[0] = 0;                         /* SDI must be 0 during read back (Fig 9) */
    hall_spi_tx[1] = 0;
    hall_spi_tx[2] = 0;
    hall_spi_tx[3] = 0;
    HALL_Read_Instru_cnt();
    g_hall_chk.cal_r = hall_spi_rx[1];
    g_hall_chk.cal_l = hall_spi_rx[3];
    g_hall_chk.cal_times = times + 1;
    if((hall_spi_rx[1] >= 0x7C) && (hall_spi_rx[1] <= 0x84) &&
       (hall_spi_rx[3] >= 0x7C) && (hall_spi_rx[3] <= 0x84))
    {
      g_hall_chk.cal_ok = 1;
      CT16B1_DelayUs(20000);                    /* Fig 11: wait 20ms after success */
      return 1;
    }
  }
  return 0;
}

void Hall_WriteReg(uint8_t reg, uint8_t data)
{
  uint8_t head;
#if (6 == USE_HALL_SENSOR)
  /* H6: CRCWR covers 6 address bits and 8 data bits (datasheet 7.4) */
  head = (reg & 0x3F) | 0x80 | (bit_crc_write_reg[data] ^ bit_crc_write_reg[reg & 0x3F]);
#else
  head = reg | 0x80 | bit_crc_write_reg[data];
#endif
  hall_spi_tx[0] = head;
  hall_spi_tx[1] = data;
  hall_spi_tx[2] = head;
  hall_spi_tx[3] = data;
  Hall_write_register();
}
