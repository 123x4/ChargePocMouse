# H5 → H6 霍尔芯片移植讲义

> 本文件是最初的文字版，之后的更新（包括原理图核对结果）只写进了同目录的 `H6移植讲义.html`，请以 HTML 版为准。

适用工程：`EM_HapticMouse`（LPC11U35，板型 `GT_LINA_T1A_H5_PWM`）
目标：把霍尔芯片驱动从 H5（GTRY154）改成 H6（GTRY164）
前提：**手上只有 H6 的板子，没有 H5 的板子**

讲义里的代码是对照芯片手册和 XENO 工程写的，**没有编译过，也没有上板验证过**。每个数值后面都标了来源，遇到和实测不符的地方，以实测和手册为准。

## 0. 怎么用这份讲义

三条规则，比任何一段代码都重要：

1. **一次只改一件事，改完就验证。** 时序错、校验位错、寄存器值错，现象都是"读出来不对"。一口气全改完再烧录，你将无法分辨是哪一个错。
2. **上一步没通过，不做下一步。** 每一步末尾都有"通过标准"，是具体的数值，不是"看起来正常"。
3. **每通过一步，提交一次，并填第 9 节的记录表。** 出问题时能退回到上一个确定正常的状态。

没有 H5 板子带来两个后果，讲义已经按此调整：

- 你**没有"已知正常"的硬件可以回退**。所以第 1 步用"编译结果逐字节相同"来证明重构没改坏，而不是上板测试。
- 你**没有 H5 的原始值作为手感基准**。第 3 节列了替代办法。

## 1. 背景知识

### 1.1 这颗芯片是什么

- H5 = GTRY154，H6 = GTRY164，都是 G.TECH 的霍尔传感器，封装和引脚相同。
- 它检测按键下方磁铁的远近，输出一个 14 位数值（0–16383）。没有磁场时约为 8192，磁铁靠近时数值向一边偏。
- 手册（datasheet）在 `资料/` 目录：
  - H6：`GTRY164 Magnetic Keyboard Sensor and LED Driver_V1.9_20261008 (Gtech)(1).pdf`
  - H5：`GTRY154 Magnetic Keyboard Sensor and LED Driver_V1.1_20240719 (For Corsiar).pdf`

### 1.2 这块板子怎么接的

两颗芯片串成一条链（菊花链），共用三根线接到 MCU 的 SSP1：

| 信号 | MCU 引脚 | 出处 |
|---|---|---|
| SCK | PIO1_15 | `src/SPI.c:227` |
| MOSI（芯片的 SDI） | PIO0_21 | `src/SPI.c:216` |
| MISO（芯片的 SDO） | PIO0_22 | `src/SPI.c:221` |

- SPI 配置是 CPOL=0、CPHA=1、8 位，时钟 48MHz ÷ (8 × 3) = **2MHz**（`src/SPI.c:238-239`，旁边注释写的 8MHz 是错的）。手册要求高于 1MHz，满足。
- 一次传输 4 个字节：`hall_spi_rx[0..1]` 是**右键**，`hall_spi_rx[2..3]` 是**左键**。
- 没有片选线。

### 1.3 "TD 时间"是什么

因为没有片选，MCU 通过**把 SCK 拉高一段特定时长**来告诉芯片要做什么。时长不同，命令不同。这个时长就是手册 7.8 节的 td。

H6 的命令（手册 7.8 节）：

| 命令 | SCK 拉高时长 | 之后的等待 | 作用 |
|---|---|---|---|
| HAL_CONVERT | td1 = 5us ±5% | td2：连续模式 >4us，单次模式 >24us | 读采样 |
| Interrupt_Mode_EN | td3 = 12us ±5% | — | 进中断模式（本项目不用） |
| W_PWM_REG | td4 = 18us ±5% | td5 >3us | 写 LED 的 PWM |
| WR_REG | td6 = 39us ±5% | td5 >3us | 结束一次读/写寄存器 |
| SLEEP | td7 = 28us ±5% | — | 休眠（本项目不用） |
| FREQ_Calibrate | td10 = 128us ±5% | td12 >50us | 频率校准 |
| Soft_RST | td11 >1280us | td9 >50us | 软复位 |

±5% 的意思是：39us 的命令，实际脉宽必须落在 37.05–40.95us。所以同事说"TD 时间要自己量"。

### 1.4 四种帧格式（手册 7.2–7.6 节的图）

**读采样**：先发 5us 脉冲，等 td2，再打 16 个时钟，每颗芯片吐出 16 位。

```
bit15  bit14  bit13 ............ bit0
CRC1   CRC0   D13 ............... D0
CRC0 = D0^D2^D4^D6^D8^D10^D12
CRC1 = D1^D3^D5^D7^D9^D11^D13
```

读到 `0xC000` 或 `0x3FFF` 表示芯片状态异常，需要复位。

**写寄存器**：先移入 16 位，再发 39us 脉冲。

```
bit15  bit14   bit13..bit8   bit7..bit0
1      CRCWR   地址 A5..A0   数据 D7..D0
CRCWR = A5^A4^A3^A2^A1^A0 ^ D7^D6^D5^D4^D3^D2^D1^D0
```

CRCWR 算错，芯片直接丢弃这次写入，不报错。

**读寄存器**：先移入 16 位（bit15 = 0，地址同上，数据任意），发 39us 脉冲，再打 16 个时钟，读回 16 位，低 8 位有效。

**频率校准**：发 128us 脉冲，等 td12，再打 16 个时钟（SDI 保持 0），读回 16 位，低 8 位有效，合格范围 0x7C–0x84。

## 2. H5 和 H6 的差异

| 项目 | H5 | H6 | 要不要改 |
|---|---|---|---|
| 读采样的命令、数据格式、CRC | td1 = 5us | 相同 | 不用 |
| 读采样后的等待（连续模式） | >2us | >4us | 宏已预留为 6us |
| 写寄存器命令 | td4 = 24us | **td6 = 39us** | 要改 |
| 频率校准命令 | td7 = 128us | **td10 = 128us**，等待 >50us | 要改 |
| 写寄存器校验位 | 只算 8 位数据 | **6 位地址 + 8 位数据** | 要改 |
| 寄存器表 | 0x0A–0x27 | 0x05–0x35，地址和含义全不同 | 整表重写 |
| LNA 增益档位 | 8/16/32/64/128x | 16/24/48/96x，联动 0x09、0x29、0x2A | 重新选 |
| 输入高电平门限 VIH | 0.5×VDD | **0.8×VDD** | 查原理图 |
| 软复位命令 | 无 | 有（td11） | 可选 |

**最大的坑**：现有代码按编号使用宏，写寄存器用 `TD4_DELAY_US`，频率校准用 `TD7_DELAY_US`。而 H6 那组宏里 TD4 = 18us（写 PWM）、TD7 = 28us（SLEEP）。只把 `USE_HALL_SENSOR` 改成 6，结果是写寄存器变成写 PWM、上电校准变成让芯片休眠，而且编译不报任何错。第 1 步专门解决这个问题。

**通过标准**：三条命令的脉宽全部在允许范围内。

## 7. 第 4 步：改校验位，写一个寄存器再读回

**目标**：证明写寄存器的帧格式和校验位是对的。

### 改动

先修一个现有的笔误。`app/button.c:921` 和 `:923`：

```c
	hall_spi_rx[1] = 0x55;//any value      →  hall_spi_tx[1] = 0x55;//any value
	hall_spi_rx[3] = 0x55;//any value      →  hall_spi_tx[3] = 0x55;//any value
```

在 `Hall_write_register` 后面加一个写单个寄存器的函数：

```c
void Hall_WriteReg(uint8_t reg, uint8_t data)
{
	uint8_t j;
	uint8_t head;

#if (6 == USE_HALL_SENSOR)
	/* H6：校验位 = 6 位地址和 8 位数据一起求奇偶 */
	head = reg | 0x80 | (bit_crc_write_reg[data] ^ bit_crc_write_reg[reg & 0x3F]);
#else
	/* H5：校验位只算 8 位数据 */
	head = reg | 0x80 | bit_crc_write_reg[data];
#endif

	for(j = 0; j < 2; j++)
	{
		hall_spi_tx[j * 2 + 0] = head;
		hall_spi_tx[j * 2 + 1] = data;
	}

	Hall_write_register();
}
```

为什么异或一次就行：`bit_crc_write_reg[x]` 返回的是"x 的奇偶，放在 bit6"。两个奇偶值异或，就是把两段合起来算的奇偶，位置仍在 bit6，正好是帧里 CRCWR 的位置。

在 `inc/button.h` 加声明 `void Hall_WriteReg(uint8_t reg, uint8_t data);`。

把 `ana_hall2_phy_set_mode`（`app/button.c:938`）改成调用它，这样校验逻辑只有一处：

```c
void ana_hall2_phy_set_mode(unsigned char length)
{
	unsigned char i;

	(void)length;
	for(i = 0; i < REG_CNT; i++)
	{
		Hall_WriteReg(sensor_reg_init_array[i][0], sensor_reg_init_array[i][1]);
	}
}
```

把第 2 步临时加的那行读寄存器换成一段写读测试：

```c
	Hall_WriteReg(0x30, 0x21);                              /* 0x30 默认值是 0x20 */
	Hall_ReadReg(0x30, (uint8_t *)&g_hall_dbg.reg_rd[1],    /* 左键 */
	                   (uint8_t *)&g_hall_dbg.reg_rd[0]);   /* 右键 */
```

选 0x30 的原因：它是"基线正偏差"，只有打开芯片内基线功能才起作用，本项目不开，改它没有副作用。

### 验证

**通过标准**：`g_hall_dbg.reg_rd[0]` 和 `reg_rd[1]` 都是 0x21。

### 不通过怎么查

| 读回值 | 含义 |
|---|---|
| 0x20 | 读是通的，写没生效。校验位算错，或 39us 脉宽不对 |
| 0x00 / 0xFF | 读本身不通。回第 2 步量 39us |
| 一个 0x21 一个 0x20 | 两颗芯片收到的帧不一样，检查 `tx[0..1]` 和 `tx[2..3]` 是否都填了 |

为了确认校验位确实在起作用，可以做一次反向实验：故意把 `^ bit_crc_write_reg[reg & 0x3F]` 去掉，对于地址奇偶为 1 的寄存器，写入应当失效。0x30 的二进制是 110000，奇偶为 0，测不出来；换 0x31（110001，奇偶为 1）来做这个实验。做完改回来。

**提交**：`H6：写寄存器校验位包含地址，并验证读写`

## 8. 第 5 步到第 8 步

### 8.1 第 5 步：写 H6 的初始化表

**目标**：把芯片配置成"连续转换、124us 采样间隔、典型增益"。

把 `inc/button.h:12` 的 `REG_CNT` 改成按芯片区分：

```c
#if (6 == USE_HALL_SENSOR)
#define REG_CNT					15
#else
#define REG_CNT					25
#endif
```

`app/button.c:226` 的表外面套一层 `#if (6 == USE_HALL_SENSOR) ... #else（原来的 H5 表）... #endif`，H6 的表如下：

```c
const unsigned char sensor_reg_init_array[REG_CNT][2] = {
	{0x0C, 0x83},	/* 固定值。手册第 8 节 */
	{0x26, 0x0A},	/* 固定值。手册 */
	{0x27, 0x05},	/* 固定值。手册 */
	{0x28, 0x04},	/* 固定值。手册 */
	{0x2F, 0x14},	/* 固定值。手册 */
	{0x34, 0x03},	/* 固定值。手册 */
	{0x09, 0x20},	/* bit5=1 配合 24x 增益；LED 最大电流=0，先关灯 */
	{0x0B, 0x85},	/* LNA 24x + PGA 19.2x。手册标注的 Typical */
	{0x29, 0x60},	/* 随 LNA 24x 联动。手册 */
	{0x2A, 0x28},	/* 随 LNA 24x 联动。手册 */
	{0x0F, 0x1F},	/* 采样间隔低 8 位：31 × 4us = 124us，与原 H5 配置一致 */
	{0x10, 0x20},	/* 高 4 位固定 0x2，采样间隔高 4 位 = 0 */
	{0x35, 0x27},	/* SDO 驱动 12mA，与原 H5 配置一致，也是默认值 */
	{0x32, 0x01},	/* 不翻转极性，关省电模式，低 4 位固定 0x1 */
	{0x33, 0x80},	/* 连续转换；芯片内基线、中断都不开 */
};
```

关于这张表的三个决定：

- **0x33 只开连续转换（0x80）。** XENO 工程用 0x84，多开了芯片内部的基线跟踪。但本工程的基线是 MCU 在 `src/my_misc.c:135-290` 自己算的，两套同时开会互相干扰，所以不开。
- **只写手册里有的寄存器。** XENO 还写了 0x13、0x15、0x16、0x18、0x1C、0x1E、0x20、0x25 这 8 个手册里查不到的地址，这里没有放。见第 10 节的问题清单。
- **LED 先关。** 原 H5 配置里灯是开的。板上霍尔芯片如果确实接了灯，等按键功能调通后再配 0x05–0x09 和 PWM。

`HallSensor_INIT` 恢复并加上读回校验：

```c
void HallSensor_INIT(void)
{
	uint8_t i, l, r;

	Hall_osc_calibrate();

	ana_hall2_phy_set_mode(2);

	for(i = 0; i < REG_CNT; i++)
	{
		Hall_ReadReg(sensor_reg_init_array[i][0], &l, &r);
		if((l != sensor_reg_init_array[i][1]) || (r != sensor_reg_init_array[i][1]))
		{
			g_hall_dbg.reg_rd[0] = sensor_reg_init_array[i][0];   /* 记下第一个出错的地址 */
			g_hall_dbg.reg_rd[1] = l;
			break;
		}
	}
	if(i == REG_CNT)
	{
		g_hall_dbg.reg_rd[0] = 0xAA;                              /* 0xAA = 全部一致 */
	}

	CT16B1_DelayUs(100);   /* 手册 0x33 说明：切换转换模式后至少等 50us */
}
```

**通过标准**：`g_hall_dbg.reg_rd[0] == 0xAA`。

**不通过**：`reg_rd[0]` 是第一个读回不一致的寄存器地址。个别寄存器可能本身不可读或读回值带保留位，把地址和读回值记下来，对照手册该寄存器的说明判断。

**提交**：`H6：初始化寄存器表`

### 8.2 第 6 步：读原始值

**目标**：读到稳定、通过校验的原始值。

读采样的代码（`hall_get_sample`）和校验函数都不用改。只加一段调试记录，放在 `app/button.c:346` 的 `hall_get_sample();` 之后：

```c
	{
		uint8_t k;
		for(k = 0; k < 2; k++)
		{
			if((hall_spi_rx[2 * k] & 0xC0) == (bit_error[hall_spi_rx[2 * k] & 0x3f] ^ bit_error[hall_spi_rx[2 * k + 1]]))
			{
				g_hall_dbg.raw[k] = ((hall_spi_rx[2 * k] & 0x3f) << 8) | hall_spi_rx[2 * k + 1];
			}
			else
			{
				g_hall_dbg.crc_err++;
			}
		}
	}
```

这里记录的是芯片给出的原值。`src/my_misc.c` 在后续处理中会按 `PRESS_KEY_AND_VALUE_DECREASE` 把它翻转成 `16383 - 原值`，两者不要混淆。

**通过标准**：

| 检查项 | 标准 |
|---|---|
| `crc_err` | 上电稳定后不再增长 |
| 磁铁拿远时的 `raw[0]`、`raw[1]` | 8192 附近，24x 增益下允许偏 ±700（手册 5.2 节 QOE24） |
| 静止不动时的抖动 | 记录最大值减最小值，第 7 步要用 |
| 没有出现 0xC000 / 0x3FFF | — |

**不通过怎么查**：

| 现象 | 原因 |
|---|---|
| `crc_err` 一直涨 | 5us 脉宽不对，或读采样后的等待不足 4us |
| 数值固定不变 | 连续转换没开，回第 5 步检查 0x33 是否读回 0x80 |
| 数值贴近 0 或 16383 | 饱和，增益过大或磁铁太近 |

**提交**：`H6：原始值读取正常`

### 8.3 第 7 步：按键与增益

**目标**：按键全行程对应的数值变化量足够大，且不饱和。

装好按键，分别记录左右键"松开"和"按到底"的 `raw`，算出差值。

**怎么判断增益是否合适**。没有 H5 实测基准，下面前两条是我给的经验判据，不是手册要求，拿到同事的参考值后以参考值为准：

- 松开和按到底的数值都离 0 和 16383 留出一千左右的余量，否则有饱和风险。
- 差值应远大于第 6 步记录的静止抖动。代码把全行程分成 100 段（`MAX_SEGMENT`），差值如果不到抖动的 100 倍，分段值会跳动。
- 代码要求差值不小于 100（`src/my_misc.c:301`），这是硬下限。

**调增益**：改 0x0B 时必须同时改 0x09、0x29、0x2A，四个是联动的。

| LNA 增益 | 0x09 | 0x0B | 0x29 | 0x2A |
|---|---|---|---|---|
| 16x | 0x00 | 0x85 | 0x50 | 0x20 |
| 24x（当前） | 0x20 | 0x85 | 0x60 | 0x28 |
| 48x | 0x20 | 0x95 | 0xA0 | 0x40 |
| 96x | 0x20 | 0xA5 | 0xF0 | 0x60 |

（0x0B 的低 4 位是 PGA，0x5 = 19.2x，范围 0x0–0x9，可做细调。0x09 的低 4 位是 LED 最大电流，表里按关灯写的。）

**按键方向**：现在 `inc/my_misc.h:40-41` 定义 `PRESS_KEY_AND_VALUE_INCREASE` 为 0，即"按下时原始值减小"。如果实测按下时数值变大，把它改成 1。

**依赖数值范围的常量**，增益定下来后逐个检查：

| 常量 | 位置 | 现值 | 含义 |
|---|---|---|---|
| `MAGNETIC_NOISE` | `inc/my_hallkey_func.h:23` | 60 | 上电找基线时允许的抖动 |
| `FILTER_SKIP_VALUE` | `src/my_misc.c:424` | 60 | 超过这个变化量就不滤波、直接跟随 |
| 基线校准里的各阈值 | `src/my_misc.c:162-290` | 多处 | 对照实测抖动重新评估 |

**通过标准**：左右键点击可靠触发和释放，慢按慢放时分段值单调变化、不来回跳。

**提交**：`H6：确定增益与阈值`
