充电调试第 2 课（上）：Charger_Init() 怎么和芯片接上头

2026-11-10 · ChargePocMouse / EM_HapticMouse · src/my_charger.c 第 56–79 行

Charger_Init() 跨了两层抽象：先在单片机引脚层配好 I2C 的两个脚和 /CE 脚，再在芯片寄存器层通过 I2C 读写 BQ21128。本节讲前 3 步，也就是“接上头”；第 4–6 步“配置芯片”放在下半节。

第 1 步：初始化 I2C 引脚（第 60 行）

soft_i2c_init(&handleI2c1);   // handleI2c1：SCL = PIO0_4，SDA = PIO0_5

“软件 I2C”：LPC11U 自带硬件 I2C 模块，但这里没用，而是用普通 GPIO 一位一位地拉高、拉低来模拟 I2C 波形，实现在 src/my_i2c.c。

物理层要先懂一件事：I2C 总线上的器件只会把线拉低，从不主动输出高电平，线上的高电平靠外接的上拉电阻拉上去。BQ21128 手册的引脚表（第 5 页）也要求 SDA、SCL 各通过 10 kΩ 接到逻辑电源。所以 soft_i2c_init 把两个脚设成开漏输出后“松开”（my_i2c.c 第 161、166 行）：不是输出高电平，而是放手，让电阻把线拉高。

单片机手册怎么说：PIO0_4 和 PIO0_5 是真正的开漏引脚，硬件上就不能输出高电平（UM10462 表 80，第 89 页：“PIO0_4 (open-drain pin)”）。所以外部上拉电阻是必需的。实测日志里 part 0x13 读对了，说明上拉是有的。

这层抽象在这里漏了：soft_i2c_init 是给“任意引脚”写的通用代码，会改 IOCON 的第 3、4 位（上下拉）和第 10 位（开漏）。可 PIO0_4/5 是特殊引脚，这几位在它们身上是保留位（表 80：第 7:3 位、第 31:10 位保留；手册修订记录：“Bit 10 changed to reserved for PIO0_4 and PIO0_5”）。手册还建议这两个脚当 GPIO 用时把 I2CMODE（第 9:8 位）设成 01，代码保持的是默认 00。目前通信正常，先记下不急着改。教训：通用代码遇到特殊引脚时，要回去对照那个引脚自己的寄存器表。

第 2 步：/CE 输出低电平（第 119–121 行）

LPC_IOCON->PIO0_1 &= ~0x07;       // ① 引脚功能选 GPIO
LPC_GPIO->CLR[0] = (0x01 << 1);   // ② 输出锁存器先写 0
LPC_GPIO->DIR[0] |= (0x01 << 1);  // ③ 再切换成输出
行寄存器含义单片机手册
①IOCON_PIO0_1 第 2:0 位 FUNC0 = 普通 GPIO。&= ~0x07 只清这 3 位，上拉设置（第 4:3 位 MODE，默认 10 = 上拉）保持不变表 77，第 87 页
②GPIO CLR往第 1 位写 1，把 P0.1 的输出值清成 0；只改这一位，不影响其他脚第 166 页
③GPIO DIR第 1 位置 1，P0.1 变成输出第 164 页

为什么 ② 必须在 ③ 前面：引脚一旦变成输出，会立刻输出锁存器里的值。如果先切成输出、再清 0，中间可能有一瞬间输出高电平，形成毛刺。先准备好“要输出的值”，再打开输出，是配置 GPIO 输出的通用习惯。

芯片这边：BQ21128 手册的引脚表（第 5 页）写道，只有 EN_CHG 位为 1，并且 /CE 引脚为低电平时才充电，两个条件缺一不可。手册还要求 /CE “must be pulled HIGH or LOW, do not leave floating”，不能悬空。这一步解决“引脚”那个条件；寄存器那个条件在第 6 步。

第 3 步：读型号，确认通信（第 63–68 行）

if(Charger_Read(REG_PART_INFO, &val))    // 读 0x38；返回非 0 = 失败
{
  InfoLog("charger no ACK");
  return -1;                             // 直接退出，第 4–6 步都不执行
}
InfoLog("charger part info 0x%02X (expect 0x13)", val);

0x13 怎么来的（BQ21128 手册表 6-42，第 58 页）：

0x13 = 00 010 011
       │   │   └── 第 2:0 位 DEV_REV = 011 = 3（芯片版本）
       │   └────── 第 5:3 位 PN      = 010 = 2（2 = BQ21128）
       └────────── 第 7:6 位 保留
  1. 这里只打印，不判断。只要 I2C 有应答，代码就继续往下走。而且 0x13 里含版本号，换一批版本不同的芯片，值就会变（比如 0x14）。真要判断“是不是 BQ21128”，只该看 PN 那 3 位：((val >> 3) & 0x07) == 2。
  2. 失败了 return -1，但没人处理这个返回值。device.c 第 436 行调用 Charger_Init(); 时没有接返回值。后果没有听上去那么严重，见思考题。
